#### Problemas encontrados e corrigidos

**🔴 Data leakage — `ainda_ativo` não significava "ativo hoje"**
- 100% dos 2.280 pares `ainda_ativo = TRUE` tinham `ultimo_ano_corrente = 2021`
- Era simplesmente truncamento da base (MIDES MG termina em 2021), não status real
- **Correção:** renomeado para `sem_evidencia_saida` + adicionadas colunas `censura_esquerda` e `censura_direita`

**🟡 `flag_continuo = "continuo"` para 425 pares com 1 único pagamento**
- Trivialmente correto por matemática (1 == 1), mas semanticamente errado
- Um município que pagou só em 2017 não tem o mesmo perfil de quem pagou 2014–2021
- **Correção:** nova categoria `"ponto_unico"` para `n_anos_pagamento == 1`

**🟡 Dupla censura — 65 pares com único pagamento em 2014**
- Não sabemos quando entraram (pode ser pré-2014) nem quando saíram
- **Tratamento:** capturados por `censura_esquerda = TRUE` + `flag_continuo = "ponto_unico"`

**🟡 133 pares com saída aparente em 2020**
- `sem_evidencia_saida = FALSE` mas `ultimo_ano_corrente = 2020`
- Podem ser saídas reais ou gaps antes de 2021 — não distinguível sem fonte adicional
- **Tratamento:** identificáveis via `ultimo_ano_corrente < 2021`

**🟢 Outlier investigado — Betim × CISMEP: R$264M**
- **Real, não erro:** Betim (~450k hab.) pagou ~R$66M/ano ao CISMEP em 2014–2017
- Queda estrutural real em 2018 (R$66M → R$3M): possível mudança de modelo de gestão
- CISMEP = consórcio de saúde com 58 municípios; Betim é o maior pagador
- CNPJ CISMEP: `05802877000110`

**🟢 19 `sem_evidencia` com `valor_total > 0`**
- Correto: valor vem de restos a pagar (dívidas de anos anteriores)
- Não são evidência de participação ativa — identificáveis via `confianca == "sem_evidencia"`

### Como cada fonte foi usada

**MIDES (4 pts)**
Todos os 2.835 pares recebem 4 pts por definição — já estão na base porque o MIDES registrou pagamento (corrente ou restos a pagar) para esse par.

**SICONFI (3 pts) — confirmação indireta por ano**
```
Para cada par (município × consórcio):
  1. Pega anos em que MIDES registra pagamento CORRENTE
  2. Verifica se SICONFI confirma pagamento a ALGUM consórcio
     no MESMO ano (rubrica .71.)
  3. Se ao menos 1 ano bate → siconfi_confirma = TRUE → +3 pts

Nota importante: SICONFI NÃO identifica para qual consórcio
foi o pagamento (sem CNPJ destino). A confirmação é indireta.
Cobertura usada: apenas nota_cobertura = "ok" (2013–2024).
Excluídos: "pre_rubrica_71" (2010–2012) e "ano_incompleto" (2025).
```

**MUNIC (2 pts) — declaração de filiação, sem cruzamento por ano**
```
Para cada par (município × consórcio):
  Verifica se o município declarou participação nesse consórcio
  em QUALQUER dos cortes disponíveis (2015 ou 2019).
  Se sim → munic_confirma = TRUE → +2 pts

Nota: MUNIC é autodeclaratório, sem cruzamento de ano.
Se declarou em 2015, vale para o par inteiro.
Cobertura: apenas 2015 e 2019 (IBGE retirou a seção após 2019).
```

**Bug corrigido — chave de join do MUNIC:**
O `cod_ibge` no MUNIC tem **6 dígitos** (ex: `310020`), enquanto o `id_municipio` no painel tem **7 dígitos** (ex: `3100203` — com dígito verificador). O join direto retornava 0 matches. Correção:
```r
mutate(id_municipio_6 = substr(as.character(id_municipio), 1, 6)) |>
left_join(munic_score, by = join_by(id_municipio_6 == id_municipio, documento_credor))
```
Resultado após correção: **1.348 pares com MUNIC confirmado** (era 0 antes do fix).

### 🔴 Ponto para Paulo: os 19 pares "sem evidência" merecem 4 pts MIDES?

**Contexto:** 19 pares estão no MIDES, mas apenas com *restos a pagar* (dívidas de anos anteriores sendo liquidadas). Nunca tiveram um pagamento corrente registrado entre 2014–2021.

**Hoje:** todos recebem `pontuacao_mides = 4` porque estão no painel MIDES.

**O problema:**
```
Par normal:
  MIDES 2016: pagamento_corrente = TRUE
  → prova direta que o município repassou o rateio
  → 4 pts faz sentido ✅

Par sem_evidencia (19 casos):
  MIDES 2016: restos_a_pagar = TRUE, corrente = FALSE
  → município liquidou uma dívida antiga
  → não sabemos quando foi o pagamento original
  → não conseguimos definir nem ano de entrada
  → 4 pts é justo? ❓
```

**Opções a decidir:**
- **Manter 4 pts:** restos a pagar ainda é evidência fiscal no MIDES
- **Reduzir para 2–3 pts:** reflete incerteza maior (sem data de entrada, sem corrente)
- **Flag especial:** manter 4 pts mas marcar `confianca = "sem_evidencia"` (já feito) e deixar analista decidir o uso

Dos 19, **6 também têm MUNIC confirmado** (chegam a 6 pts). Esses 6 são os mais robustos: MUNIC declara filiação formal + MIDES mostra alguma movimentação financeira, mesmo que só restos.

## Etapa 7b — Painel Universal MG (concluída em 2026-05-14)

### O que fizemos

Construímos o script `05_painel_universal_mg.R`, que expande o universo de pares do sistema de pontuação. Em vez de ancorá-lo exclusivamente no MIDES (2.835 pares), o painel universal usa a **união de MIDES + MUNIC**, restrita aos 223 consórcios do cadastro MG.

O produto é `2026-05-14_painel_universal_mg_v1.csv/.xlsx`.

---

### Por que isso importa

O script 04 (v2) era cego para municípios que declararam filiação no MUNIC mas nunca aparecem no MIDES. Isso captura três situações reais:
1. Município membro de consórcio informal (não Lei 11.107 → sem rubrica MIDES)
2. Município inadimplente (declarou filiação, não pagou)
3. Município com pagamentos pré-2014 (MIDES MG começa em 2014)


### Lógica de construção do universo

```r
# Pares MIDES (origem = "mides")
pares_mides <- painel_mg_participacao |>
  mutate(cod_ibge_6 = substr(id_municipio, 1, 6),
         cnpj_consorcio = documento_credor, origem = "mides")

# Pares MUNIC (origem = "munic") — restritos ao cadastro MG

universo <- bind_rows(pares_mides, pares_munic) |>
  summarise(
    tem_mides      = any(origem == "mides"),

  )
```

### Lógica SICONFI — dupla âncora

SICONFI não identifica o consórcio destinatário. Por isso a confirmação depende de saber **em quais anos** o município deveria ter pago aquele consórcio:

**Âncora MIDES** (para os 2.835 pares com MIDES):
```
Anos âncora = anos com pagamento corrente no MIDES
Se SICONFI confirma pagamento a "algum consórcio" em ao menos
1 desses anos → siconfi_confirma = TRUE → +3 pts
```

**Âncora MUNIC** (para os 52 pares só MUNIC):
```
Anos âncora = cortes disponíveis (2015 e/ou 2019)
Mesma lógica: se SICONFI confirma em ao menos 1 desses anos
→ siconfi_confirma = TRUE → +3 pts
```

### Bugs encontrados e corrigidos

**Bug 1 — Chave SICONFI em 7 dígitos (não 6)**
`siconfi_mg` tem `cod_ibge` de 7 dígitos. O universo usa `cod_ibge_6` (6 dígitos). O join direto via rename não convertia — retornava 0 matches.
```r
# Correção: aplicar substr no momento do carregamento
siconfi_mg <- read_excel(...) |>
  mutate(cod_ibge_6 = substr(as.character(cod_ibge), 1, 6)) |>
  select(cod_ibge_6, ano, paga_consorcio)
```

**Bug 2 — `ancora` NA para 19 pares sem_evidencia**
Esses 19 pares têm origem MIDES mas nunca tiveram pagamento corrente. Ficaram fora do `siconfi_mides` (âncora MIDES requer corrente) e também fora do `siconfi_munic` (são MIDES, não MUNIC-only). Resultado: `ancora = NA` após o join.
```r
# Correção: fallback explícito
ancora = if_else(is.na(ancora), "sem_ancora", ancora)
```

**Bug 3 — Duplicatas por setor no munic_mg (mais sutil — detectado no EDA)**
`munic_mg` tem 1 linha por setor por (município × consórcio × ano). Um consórcio multissetorial com 12 setores gera 12 linhas para o mesmo par-ano. Sem `distinct()`, o join com SICONFI multiplicava as linhas → `n_anos_siconfi_match` chegava a 12 (impossível, MIDES MG cobre no máximo 8 anos).
```r
# Correção: distinct antes do join com SICONFI
munic_mg |>
  distinct(cod_ibge_6, cnpj_consorcio, ano) |>   # deduplicar por setor
  left_join(siconfi_mg, by = join_by(cod_ibge_6, ano))
```
⚠️ Este bug NÃO foi detectado na revisão pré-execução — só apareceu no EDA. **Lição:** sempre fazer `count(cod_ibge, cnpj_consorcio, ano) |> filter(n > 1)` antes de join com `munic_mg`.
